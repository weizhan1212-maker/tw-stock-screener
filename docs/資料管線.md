# 資料管線說明（第 1 階段）

> 給之後維護的人（或 Claude）看：資料從哪來、存在哪、怎麼跑、出問題怎麼查。

## 1. 架構

```
證交所／櫃買（每 3 秒一次，兩站交錯）──┐
OpenAPI（月營收、季報偵測、公司資料）──┼─→ pipeline（Python，GitHub Actions 執行）─→ Supabase Storage
FinMind（財報、月營收、股利；每小時 600 次）┘                                       bucket: market-data（私有）
```

## 2. 資料集（Supabase Storage `market-data/master/`）

### 日資料：依月份分檔 `master/{資料集}/{YYYY-MM}.parquet`

| 資料集 | 鍵 | 主要欄位 | 來源 |
|---|---|---|---|
| prices | date, code | open, high, low, close, volume（股）, value（元）, trades；櫃買另有 shares_issued, ref_next（次日參考價） | 證交所 MI_INDEX、櫃買 dailyQuotes |
| insti | date, code | foreign（含外資自營商）, trust, dealer, total（股） | 證交所 T86、櫃買 dailyTrade |
| margin | date, code | margin_prev/buy/sell/redeem/balance、short_prev/sell/buy/redeem/balance、offset（張） | 證交所 MI_MARGN、櫃買 margin/balance |
| valuation | date, code | pe, pb, dividend_yield | 證交所 BWIBBU_d、櫃買 peQryDate |
| qfii | date, code | shares_issued, foreign_shares, foreign_ratio | 證交所 MI_QFIIS（有歷史）、櫃買 OpenAPI（只有每日最新） |
| exright | date, code | prev_close, ref_price, value, kind | 證交所 TWT49U；櫃買由 ref_next 推算（kind=推算） |
| index | date | taiex（加權指數）, taiex_tr（報酬指數） | 證交所 MI_INDEX |

每列都有 `market`（TWSE／TPEX）。**只收普通股（4 位數、不以 0 開頭）與 ETF（00 開頭）**，權證、特別股、ETN、TDR 一律濾掉。

### 其他表：單一檔 `master/{表}.parquet`

| 表 | 鍵 | 說明 |
|---|---|---|
| income／balance／cashflow | code, date, type | FinMind 長表（type 為科目代號，例：EPS、Revenue）；資產負債表已去掉 `_per` 百分比列 |
| revenue | code, year, month | FinMind 月營收歷史（元） |
| revenue_latest | code, year, month | OpenAPI 最新一期月營收（千元已換算成元）；**讀取時與 revenue 合併，revenue_latest 優先** |
| dividend | code, date, period | 現金股利 cash、股票股利 stock、除息日、除權日 |
| securities | code | 股票清單：名稱、產業、市場、類型（stock／etf） |
| company | code | 上市櫃公司基本資料：產業代碼、上市日、發行股數、資本額 |
| delisting | code | 下市清單（回測避免倖存者偏差） |
| income_periods | code, year, quarter | OpenAPI 顯示各公司已公布的最新一季（用來決定季報補抓） |

### 進度狀態 `master/_state/*.json`

| 檔案 | 內容 |
|---|---|
| days.json | 每個日期的狀態：`holiday`，或各端點 `ok`／`pending`（今天還沒公布）／`nodata1`／`missing`（放棄）／`error:…`；`_tries` 為失敗次數 |
| exright_months.json | 證交所除權息已抓的月份 |
| finmind_backfill.json | 每檔已完成的 FinMind 資料集；`_complete` 全部完成旗標 |
| fin_queue.json | 待補抓新一季財報的公司 |

## 3. 指令

```bash
python -m pipeline daily              # 每日：抓近 10 天缺的資料＋參考資料
python -m pipeline backfill-daily     # 歷史日資料回補（預設 4 年，--chain 自動接力）
python -m pipeline backfill-finmind   # FinMind 回補（預設 8 年）
python -m pipeline fin-refresh        # 季報補抓（FinMind 回補完成後才會動作）
python -m pipeline report             # 資料檢查報告
```

沒設定 `SUPABASE_URL`／`SUPABASE_SERVICE_KEY` 時會改寫本機 `data/` 資料夾（測試用）。

## 4. GitHub Actions

| Workflow | 用途 | 觸發 |
|---|---|---|
| 測試（ci.yml） | 跑 tests/（用 tests/fixtures 的真實回應樣本） | push |
| 每日資料更新（daily.yml） | daily ＋ fin-refresh | 目前手動；回補完成、公布時間確認後開排程 |
| 歷史資料回補（backfill.yml） | job=daily／finmind／smoke；chain=true 跑不完自動接力（沒進度就停） | 手動 |
| 擷取測試樣本（capture-fixtures.yml） | 更新 tests/fixtures | 手動／改腳本時 |
| PoC（poc.yml） | 公布時間探測 | 交易日排程（PoC 結束後刪除） |

**同時執行規則**：daily、日資料回補、季報補抓同屬 `pipeline-days` 群組（排隊，不會同時跑）；FinMind 回補獨立。季報補抓在 FinMind 回補完成前會自動跳過，避免兩個任務同時寫財報檔。

## 5. 查問題

- **執行紀錄**：每次執行的完整紀錄存在 `run-logs` 分支 `logs/<run_id>-<attempt>-<job>.log`（GitHub 網頁的 Actions 頁也看得到）
- **資料對不對**：跑 `report`，看每日檔數（正常約 2,330 檔行情）、缺值比例（pe 約 20% 缺值屬正常：虧損公司沒有本益比）
- **某天缺資料**：看 `days.json` 該日狀態；`missing` 代表重試 3 次仍失敗，可手動刪掉該日狀態後重跑 daily
- **櫃買偶爾 `Response ended prematurely`**：櫃買伺服器斷線，程式會自動重試，屬正常
- **欄位格式改變**：解析器會丟出錯誤（例：櫃買三大法人欄位數不是 24、加總不符），照錯誤訊息更新 `pipeline/sources/`，並用 `capture-fixtures` 重抓樣本更新測試

## 6. 網站用的檔案（Supabase Storage `market-data/site/`）

| 檔案 | 產生指令 | 內容 |
|---|---|---|
| `site/snapshot.json.gz` | `python -m pipeline snapshot` | 每檔最新一天約 117 個指標（篩選、策略、排行、個股頁標頭與評級都用它） |
| `site/market.json.gz` | `python -m pipeline market` | 市場總覽、排行榜 |
| `site/stock/{代號}.json.gz` | `python -m pipeline stocks [--codes 2330,0050]` | 個股頁：日 K（原始價＋還原因子）、法人、融資、月營收 60 個月、季財報 20 季、股利、集保大戶 52 週 |

每日任務（daily.yml）依序：daily → fin-refresh → snapshot → market → stocks → report。

### 集保股權分散（holders）

- 來源：集保結算所開放資料 `https://opendata.tdcc.com.tw/getOD.ashx?id=1-5`（CSV，每週五更新，只有最新一週）
- 存成日資料集 `holders`（鍵：date、code），欄位：holders（總人數）、holders_1000、pct_1000（千張以上）、pct_400（400 張以上）、pct_retail（10 張以下）
- 歷史無法回補，從上線起每週累積
